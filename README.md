# 东方财富条件选股结果

这是一个部署在 GitHub Pages 上的单页股票筛选页面。前端通过 Cloudflare Worker
读取东方财富数据，并按表格方式做分组和汇总展示。

## 功能

- 通过 Cloudflare Worker 读取东方财富数据
- 展示最新价、市盈率、市净率、总市值等基础指标
- 展示净资产收益率、毛利率、净利率等财务指标
- “经营活动现金流”分组展示近三个完整年度的现金流金额和累计净现比，支持排序及按净现比倍数筛选
- 展示合同负债及其同比、环比增长数据
- 表头按时间和指标分层显示，便于横向对比
- 页面可直接部署到 GitHub Pages

## 直接使用

打开 <https://wanliyunyan.github.io/stock/> 即可。未进行任何配置时，页面默认使用：

```text
https://stock.88527712pan.workers.dev
```

## 配置自己的 Worker

用户可以通过 `api` 查询参数切换到自己的 Worker。例如：

```text
https://wanliyunyan.github.io/stock/?api=https://your-worker.workers.dev
```

访问一次后，Worker 地址会保存到当前浏览器。以后直接打开页面时，仍会使用该地址。

Worker 地址按以下优先级选择：

1. 当前 URL 中的 `api` 参数
2. 当前浏览器已经保存的 Worker 地址
3. 项目内置的默认 Worker 地址

更换 Worker 时，使用新的 `api` 参数重新访问一次即可。要清除自定义配置并恢复默认值，
先访问 `https://wanliyunyan.github.io/stock/?api=`，再重新打开首页。

## 部署到 GitHub Pages

前端不需要构建，可以直接发布为静态站点：

1. 把 `index.html` 推到 GitHub 仓库根目录
2. 在 GitHub 仓库设置里打开 Pages
3. 选择 `main` 分支和根目录作为发布源
4. 保存后等待 GitHub Pages 生成链接

## 部署自己的 Cloudflare Worker

仓库根目录的 `worker.js` 是 Cloudflare Worker 模块代码：

1. 在 Cloudflare Workers 中创建一个 Worker
2. 使用 `worker.js` 的内容替换默认代码
3. 部署并取得形如 `https://your-worker.workers.dev` 的访问地址
4. 直接打开该地址，确认返回内容中的 `ok` 为 `true`
5. 按“配置自己的 Worker”一节将地址写入页面

Worker URL 是公开的接口地址，不是密钥。不要把 Cloudflare API Token、账户凭证或其他密钥
写入 `index.html`、`worker.js` 或提交到 Git 仓库。

## 说明

- 近三年累计净现比 = 最近三个已结束的完整年度经营活动现金流量净额合计 ÷ 同期合并净利润合计（含少数股东损益），不是三个年度净现比的平均值。
- 年份按北京时间确定：2026 年使用 2023—2025 年报。“经营活动现金流”下依次显示 `2023`、`2024`、`2025`、`累计净现比` 四个子列，年度金额按元、万元或亿元显示。不混入季报、半年报，也不以更早年度补齐缺失年份；年报尚未披露或任一年度数据缺失时显示“数据不全”，累计净利润不大于零时净现比显示“不适用”，请求失败时显示“加载失败”。
- 净现比显示两位小数，单位为“倍”，例如筛选最小值填 `1` 表示至少 1 倍。现金流与净利润金额来自现有东财选股接口，可能已经按万元、亿元等单位舍入，因此比值为近似值。鼠标悬停可查看计算口径与累计金额。设置净现比范围后，缺失、不适用和加载失败的记录不会通过该项筛选；未设置范围时保留。
- 当前版本默认通过 Cloudflare Worker 访问东方财富数据
- 查询直接提交筛选条件，不需要固定来源 ID；“来源 ID”与“来源页面”使用当前选股结果返回的 `xcId`。接口未返回 ID 时显示 `-`，链接回东财选股首页。
- Worker 提供 `/api/stocks` 和 `/api/quotes` 两个接口
- 选股请求的 `fingerprint` 在首次需要时生成 32 位十六进制随机值，并保存在当前站点的浏览器存储中；同一站点后续查询、刷新和标签页复用该值。不同浏览器、不同站点的存储各自独立；存储不可用时仅在当前页面内复用。该值是本项目生成的匿名标识，不是东财签发的身份凭证，也不保证解除频率限制。
- 没有定时刷新或自动重试。打开页面时加载一次选股、财务及行情数据；远程筛选条件输入完成（回车或离开输入框）后查询，切回标签页不会触发请求，本地筛选不访问接口。K线由预览操作触发，失败后不自动重试。
- 不缓存任何选股、财务、行情或 K 线数据，不保存或恢复本地数据快照。每次打开/刷新页面都会重新请求全部数据；相同查询和再次打开 K 线预览也会重新请求。旧版本留下的数据缓存和限流记录不再读取。
- 前端请求禁用 HTTP 缓存；行情和 K 线请求带唯一参数。Worker 向上游请求时也禁用缓存，响应使用 `Cache-Control: no-store`。
- 选股请求在当前页面串行发送并间隔至少两秒；支持 Web Locks 的浏览器会串行协调同源标签页，但不保存跨页面的等待状态。
- 东财返回 `307` 或 HTTP `429` 时显示本次限流错误，停止本轮后续选股/财务查询；上游提供 `Retry-After` 时显示其建议重试时间。不保存限流状态，不自动重试，手动刷新页面会重新发起请求。
- 行情查询独立于选股/财务查询，最新价、市盈率、市净率、总市值及当日涨跌幅一起更新。行情失败或只返回部分股票时明确提示，未取得最新行情确认的值标记“未更新”；刷新页面不会恢复之前页面的数据。
- 股息率、估值分位、区间涨跌幅等补充数据每轮重新请求；按数据源实际披露日期展示，日频指标不伪装为分秒行情。
- 适合做公开演示、个人看盘页、静态部署
